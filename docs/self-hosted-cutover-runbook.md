# FlowContext 自托管受控切换运行手册

> 状态：计划步骤，尚未执行；本手册不构成迁移已完成的证据。任何真实操作仅在操作者逐项勾选并留存已验证证据后继续；不得断言切换完成。

## 安全边界

- 不得将密码、私钥、`.env` 内容、设备令牌、注册码、数据库导出文件或服务器地址以外的凭据写入仓库、Shell 历史、项目 Context、运行手册、日志、截图或聊天。
- 只在服务器保存 `.env`，权限固定为 `0600`；本地仓库只保留 `deploy/flowcontext/.env.example`。
- 本流程不替换、停止或重载现有服务，除非每项变更均已得到用户明确批准并有可回退命令。
- 计划步骤与已验证证据必须分开记录；未记录的检查一律视为未完成。
- 已获批准的公网边界是 `flowcontext.zkabi.cn`：既有 Nginx 负责 TLS 终止，再反向代理到仅限 loopback/私有 Docker 网络的 FlowContext 服务。Caddy 不得占用 80/443。

## 计划步骤

### 1. 服务器只读预检与共存闸门

- [ ] 以当前可用账号进行**只读预检**：记录操作系统、磁盘、内存、Docker/Compose 版本、防火墙规则及 80/443 监听摘要；不安装软件、不改配置。
- [ ] 确认既有 Nginx 保持 80/443。不得用 Docker/Caddy 替换、杀死或重载现有 Nginx。
- [ ] 对已批准的 `flowcontext.zkabi.cn` 新增一个隔离 Nginx 站点：Nginx TLS 终止后，仅反向代理到 FlowContext 的 loopback/私有 Docker 网络服务；不得让 PostgreSQL 或 API 暴露公网端口。
- [ ] **Task7.5 必须先修复部署资产**：当前 Caddy Docker Compose 方案会发布 80/443，与批准的 Nginx 共存模式冲突。修复为 Nginx→loopback/私有容器方案并通过部署契约测试前，禁止执行部署脚本。
- [ ] 在隔离边界可行后，复查 `flowcontext.zkabi.cn` 的 DNS、Nginx TLS 路由和 `/healthz`；不得影响已有 Nginx 站点。

### 2. 受控部署账号

- [ ] 首次仍可用原有管理路径时，创建最小权限的非 root SSH 部署账号并添加专用 SSH key。
- [ ] 用该非 root SSH key 建立第一次独立会话，验证其仅能访问部署目录和 Docker 所需权限。
- [ ] 关闭原会话后，以该 key 进行**第二次独立登录**；仅在这次登录成功后，才评估 SSH 加固（例如限制 root 登录）。不得在第二次独立登录前修改 root/SSH 登录策略。
- [ ] 在服务器部署目录创建 `.env`、执行 `chmod 0600 .env`，并确认没有将实际值复制进 Shell 历史或仓库。

### 3. 部署及外部边界验收

- [ ] 仅在 Task7.5 的 Nginx→loopback/私有容器部署资产通过测试后运行修订后的预检；其失败时停止，不绕过 DNS、权限或 Nginx 共存检查。
- [ ] 运行修订后的部署脚本并记录容器健康状态；Nginx 是唯一公网 TLS 边界，PostgreSQL 与 API 只留在 loopback/私有网络。
- [ ] 从服务器外部执行 HTTPS `GET /healthz`，记录状态码、时间与域名；不要在证据中记录令牌或密码。
- [ ] 若部署、证书或外部健康检查失败，停止数据切换并执行本手册的回滚步骤。

### 4. 源数据冻结、备份与导入校验

- [ ] 宣布并执行源端**写入冻结**；记录冻结开始时间和操作者，冻结后不再允许新增或修改业务数据。
- [ ] 使用迁移工具导出受支持业务表到受保护目录，导出文件权限为 `0600`。
- [ ] 为导出生成 SHA-256 备份哈希，并保留导出附带的 `manifest.json`；记录文件名、哈希、行数和生成时间，不记录数据内容。
- [ ] 在独立位置进行一次备份可读性检查，核对 SHA-256 与 `manifest.json` 的清单、行数和摘要一致。
- [ ] 确认目标 PostgreSQL 是**空目标**，且 owner UUID 与导出清单一致；非空目标或 owner 不一致时停止。
- [ ] 在目标端执行事务导入；导入失败时不继续客户端切换。
- [ ] 使用迁移工具执行 `verify --input <导出目录>`，保存仅含统计结果的验证输出，核对行数、外键、最新 Handoff、To-do 与 Daily 样本。

### 5. 逐设备免登录切换

- [ ] 对每台设备分别生成唯一设备 ID，并为**每台设备**签发独立、一次性、预绑定的注册码；不得复用或批量共享注册码。
- [ ] 通过受控渠道把对应注册码输入该设备；注册码、设备令牌和设备 ID 的映射不得写入本手册或日志。
- [ ] 构建客户端产物后扫描产物与配置，确认不存在生产 Supabase URL、`supabase-js` 或 Supabase key；发现即停止发布。
- [ ] 在 macOS 安装候选桌面应用，验证首次注册码绑定、重启后静默连接、项目/Topic/Session/To-do/Daily 读取与写入、SSE 实时更新，以及撤销设备后凭据清除和重新绑定。
- [ ] 在 Windows 安装对应候选桌面应用，执行与 macOS 相同的核心检查；Windows 未实际通过时不得把跨设备切换标为完成。

### 6. 回滚

- [ ] 回滚触发条件：数据 `verify --input` 失败、外部 `/healthz` 失败、关键客户端写入/同步失败、错误域名路由，或未授权的边缘服务变更。
- [ ] 保持源端冻结和原 Supabase 数据完整；不要删除源端项目、迁移导出或数据库卷。
- [ ] 停止新客户端发布，将已切换设备恢复到原已验证版本/配置；必要时撤销新设备令牌。
- [ ] 停止仅本次新增的 FlowContext 容器和 `flowcontext.zkabi.cn` 隔离 Nginx 站点配置，不触碰既有 Nginx 其他站点。
- [ ] 以 SHA-256 与 `manifest.json` 确认备份仍可用，记录故障时间、影响范围、命令退出码和下一次安全尝试条件。
